# ARCHIVED — Handoff - IMS Using-Car Snapshot / Lifecycle Event Rework

> 2026-07-26 신규예약 오케스트레이션 재설계에서 자동 lifecycle 변경 경로를 폐기해 보관한다.

## 1. 현재 목표
IMS API의 배차중/운행 관련 조회 결과를 OPS와 연동해 자동 상태 반영을 준비하려 했으나, 구현 중 기준 오류가 반복되어 현재 작업은 **즉시 중단 및 재설계 필요** 상태다.

핵심 목표는 다음으로 재정의해야 한다.
- IMS API 응답 리스트는 로컬에서 임의 status 필터링하지 않고 그대로 snapshot 저장한다.
- 자동 판단은 snapshot 수집과 분리한다.
- OPS 자동 반영은 OPS에 이미 저장된 IMS external link가 정확히 일치하는 예약만 대상으로 한다.

## 2. 현재 상태
- 원격 DB migration 적용 안 함.
- 실제 event POST 안 함.
- 운영 DB 반영 안 함.
- launchd 연결/restart 안 함.
- 코드/테스트/migration 파일은 로컬 working tree에 변경됨.
- 현재 변경은 그대로 live 검증하면 안 된다.

## 3. 이미 결정된 사항
- IMS API가 특정 조회 조건으로 준 리스트는 그대로 snapshot에 저장한다.
- 로컬 status 필터 금지.
- `disappeared`는 자동 반납 근거가 아니다.
- 자동 반납은 현재 snapshot diff 설계에서 제외한다.
- 차번호/일정 기반 예약 매칭 금지.
- OPS 자동 반영 매칭은 `rc00_ops_external_reservation_links`의 IMS ID exact match만 허용한다.
- 차번호는 매칭 키가 아니라 보조 검증값이다.
- OPS에 IMS 연동 정보가 없는 예약은 자동 발동 금지.
