# 자동차 그룹별 가격 정책 재설정 Phase

## 목적
자동차 그룹별 가격 정책을 현재 운영 기준으로 다시 설정한다.

## 기준점
- repository: `rentcar00_OPS`
- branch: `main`
- 현재 HEAD: `ddf13e5 Organize OPS documentation structure`
- 업로드 상태: 사장님 확인 기준 현재 업로드본이 최신 운영 기준
- 현재 목표 문서: `docs/GOAL/rentcar00_OPS-current.md`

## Phase 목록

### Phase 1. 가격 정책 기준점 확인
- 자동차/차종 그룹 기준 확인
- 현재 코드의 가격 입력/저장/표시 경로 확인
- 홈페이지 예약 이벤트 가격 데이터 흐름 확인
- IMS import 가격 매핑 확인

종료 조건:
- 가격 정책이 적용되는 경로 목록이 문서화된다.
- DB/runtime/외부 서비스 직접 변경 필요 여부가 분리된다.

### Phase 2. 그룹별 가격 정책 설계
- 자동차 그룹별 정책표 초안 작성
- 예약 직접 생성/수정, 홈페이지 이벤트, IMS import 중 어디에 적용할지 확정
- 검증 기준과 되돌릴 방법 작성

종료 조건:
- 적용 대상과 제외 대상이 명확해진다.
- 사장님 승인 전 코드/DB 변경을 하지 않는다.

### Phase 3. 승인된 최소 범위 구현
- 승인된 파일만 수정
- 가격 표시/저장/검증 경로를 최소 변경
- 운영 secret, `.env`, runtime config, DB 직접 반영은 별도 승인 없이는 제외

종료 조건:
- `flutter analyze` 등 가능한 검증을 통과한다.
- 변경 범위와 남은 리스크가 보고된다.

## 리스크
- 자동차 그룹 기준이 애매하면 홈페이지/앱/IMS 가격이 서로 다르게 적용될 수 있다.
- 가격 생성 경로가 여러 개라 일부 경로만 수정될 수 있다.
- 운영 DB 직접 변경이 필요할 경우 코드 작업과 별도 승인으로 분리해야 한다.

## 되돌릴 방법
- 문서 변경은 git revert 또는 이전 커밋 체크아웃으로 되돌린다.
- 코드 변경 phase는 승인된 커밋 단위로 되돌린다.
- 운영 DB/외부 서비스 변경은 별도 승인 전까지 수행하지 않는다.
