# OPS 가격조회 버튼 이슈 보고서

- 작성일: 2026-07-22
- 프로젝트: rentcar00_OPS
- 분류: Issue / PM 후보
- 상태: 사장님 요청 기준 이슈 정리 완료, 구현 미승인

## 1. 이슈 요약

OPS에 `가격조회` 버튼 기능이 필요하다.
버튼을 누르면 날짜와 시간을 선택하고, 선택한 대여 기간 기준으로 홈페이지와 동일한 기준 금액을 조회할 수 있어야 한다.

현재 현장/관리자가 금액을 확인하려면 홈페이지 기준가를 별도로 확인해야 하므로, OPS 안에서 같은 계산 기준을 바로 확인하는 흐름이 필요하다.

## 2. 사장님 요청 기준

목표:
- OPS 화면에 `가격조회` 버튼을 추가한다.
- 버튼 클릭 시 날짜/시간을 선택한다.
- 선택한 대여 시작/반납 일시로 기간을 계산한다.
- 홈페이지 기준 금액과 동일한 금액을 보여준다.

핵심 요구:
1. 날짜 선택
2. 시간 선택
3. 기간 확인
4. 홈페이지 기준 금액 조회
5. OPS 안에서 결과 표시

## 3. 권장 구현 방향 후보

### Phase 1. 기준 금액 소스 확인

목적:
- 홈페이지에서 사용하는 가격 계산 기준과 OPS에서 참조할 기준을 일치시킨다.

확인 후보:
- 홈페이지 가격 계산 API 존재 여부
- 차량/차종/그룹별 가격 테이블
- 성수기/비수기/주말/공휴일/장기대여 할인 기준
- 보험/자차/옵션 포함 여부

종료 조건:
- OPS 가격조회가 참조할 단일 가격 기준이 확정된다.
- 홈페이지와 OPS가 서로 다른 계산식을 갖지 않도록 기준 경로가 정리된다.

검증:
- 동일 차량/동일 기간으로 홈페이지 금액과 OPS 조회 금액 비교

### Phase 2. OPS 가격조회 UI 추가

목적:
- 직원이 OPS 안에서 날짜/시간을 선택해 금액을 확인할 수 있게 한다.

수정 후보:
- 차량 상세 또는 예약 생성/수정 화면의 `가격조회` 버튼
- 대여 시작 일시 선택
- 반납 예정 일시 선택
- 기간 계산 표시
- 기준 금액 결과 표시

종료 조건:
- 버튼 클릭 → 날짜/시간 선택 → 기간 확인 → 금액 표시 흐름이 동작한다.
- 선택값이 부족하면 조회를 막고 안내한다.

검증:
- 당일/1박2일/장기대여 케이스 UI 확인
- 시작 시간이 반납 시간보다 늦은 경우 차단 확인

### Phase 3. 홈페이지 기준 금액 일치 검증

목적:
- OPS 금액이 홈페이지 기준 금액과 어긋나지 않게 한다.

검증 후보:
- 대표 차량 3종
- 평일/주말
- 24시간 미만/1일/2일 이상
- 성수기 또는 특수 요금 기간이 있으면 포함

종료 조건:
- 샘플 케이스에서 홈페이지 표시 금액과 OPS 가격조회 금액이 일치한다.
- 불일치 케이스가 있으면 계산 기준 차이를 문서화하고 수정 범위를 다시 잡는다.

## 4. 리스크

- 홈페이지와 OPS가 서로 다른 계산식을 가지면 금액 불일치가 발생한다.
- 보험/옵션/할인 포함 여부가 불명확하면 현장 안내 금액이 틀어질 수 있다.
- 성수기, 주말, 공휴일, 장기대여 기준이 빠지면 실제 예약 금액과 차이가 날 수 있다.
- 가격 기준을 앱에 하드코딩하면 추후 요금 변경 때 유지보수 위험이 커진다.

## 5. 다음 결정 필요

1. 가격조회 버튼을 어느 화면에 둘지
   - 차량 상세
   - 예약 생성/수정
   - 별도 가격조회 화면
2. 금액 기준에 보험/옵션을 포함할지
3. 홈페이지 가격 API를 그대로 재사용할 수 있는지 먼저 확인할지
4. 구현 우선순위를 기존 반납/IMS 이슈보다 앞에 둘지

## 6. 현재 결론

가장 안전한 1차 작업은 `홈페이지 가격 계산 기준 확인`이다.
OPS에 별도 계산식을 새로 만들기보다, 홈페이지와 같은 API 또는 같은 가격 정책 레이어를 재사용하는 방향이 장기적으로 안전하다.
